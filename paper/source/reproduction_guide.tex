\section*{4 Run the local-source replay}
From the extracted archive root, execute
\begin{quote}\ttfamily
bash verify.sh
\end{quote}
The script first verifies the source hashes in the manifest. It obtains the selected Lean executable and dependency search path through Lake, prepends the local directory to \texttt{LEAN\_PATH}, and compiles every local module in the listed dependency order. Each module is passed to Lean as source and produces a local object and a log in \path{verification-logs}. A nonzero compiler exit terminates the script. The final raw canonical harness is checked after the root module, and the final axiom report is validated against the standard allowed set.

A successful run must reach the concluding message
\begin{quote}\small\ttfamily
Canonical first-question theorem compiled with standard axioms only.
\end{quote}
Do not infer completion from an empty log, the existence of an object file, or a partial progress list. Retain the entire command's exit status and final logs. For a second explicit raw-statement check after a successful replay, use the full Lake dependency path as well as the local object directory:
\begin{quote}\small\ttfamily
LEAN\_PATH=".:\$(lake env printenv LEAN\_PATH)" \textbackslash\par
\quad lake env lean -M4096 VERIFY\_CANONICAL.lean
\end{quote}
The expected main-theorem axiom report contains \texttt{propext}, \texttt{Classical.choice}, and \texttt{Quot.sound}, with no \texttt{sorryAx} or custom axiom. Different successful builds need not produce byte-identical compiled objects; source identity and successful kernel checks are the relevant reproducibility claims.

If the run fails, save the failing module name, exact source hash, compiler version, dependency revision, exit status and log. Distinguish an environment or resource failure from a rejected proof. Re-running an unchanged failed module with adequate resources is different from modifying the artifact. Report any source change as a new version, not a replay of version 5.

\section*{5 Inspect the proof in layers}
\begin{enumerate}
\item Read the endpoint proof in \path{Erdos883AKEndpoints.lean}. Its odd-triple pigeonhole argument removes an external Ahlswede--Khachatrian assumption.
\item Follow smoothing, ordering and the exact criterion through \path{Erdos883Smoothing.lean}, \path{Erdos883RetentionOrder.lean}, \path{Erdos883SortedSignatures.lean}, \path{Erdos883OrderedHall.lean}, and \path{Erdos883FiniteCriterion.lean}.
\item Inspect the profile and resource bridges, including \path{Erdos883ProfileCriterion.lean} and \path{Erdos883RealResources.lean}. The two connector pools and one common skeleton must remain visible.
\item Inspect the exact finite arithmetic through the adaptive assembly files, their metadata/permutation proofs, checked count trees, and rank or span witnesses. The $88$ adaptive intervals cover $1212$ through $199999$; the preceding proved prefix covers $0$ through $1211$.
\item Follow the refined CDF bounds and analytic branches in \path{Erdos883RefinedCdfBounds.lean}, \path{Erdos883ImprovedAccounting.lean}, \path{Erdos883ImprovedRanks.lean}, \path{Erdos883ImprovedNeighbors.lean}, and \path{Erdos883ImprovedLargeNCover.lean}.
\item Finish at \path{Erdos883VerifiedCoverage.lean} and the raw canonical harness. A theorem name alone is insufficient; inspect the actual type.
\end{enumerate}
The manuscript's Appendix A and the companion \path{adaptive_intervals.csv} provide the adaptive interval list. Their endpoints were extracted from the final root and checked for count, first and last endpoints, and adjacency during manuscript preparation.

\section*{6 Interpret the existing evidence precisely}
The delivered audit records modular kernel source compilation during construction, targeted recompilation of identified correspondence concerns, a fresh final-root check, the explicit raw-type check, a local-source safety scan, and unchanged frozen source/object/configuration hashes during that final check. This supports the stated formal result.

It is not a claim that every numerical certificate was rebuilt twice from scratch in an independent environment. Some construction-time module compilations have historical execution evidence but no durable per-module pre/post hash attestation. The package explains that distinction. A successful fresh run of Section 4 would add a clean local-source replay; this guide has not performed or certified that additional run. Neither the existing audit nor such a replay is independent human review or a separate Lean-kernel implementation.
